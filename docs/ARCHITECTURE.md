# 实现与工程约定

## 模块边界

| 模块                          | 职责                                           |
| ----------------------------- | ---------------------------------------------- |
| `src/core`                    | 纯协议校验、坐标与旅行计算；不依赖浏览器和渲染 |
| `src/generator`               | 不透明来源隔离、Worker 生成、数据白名单        |
| `src/engine/flight.ts`        | 输入与连续运动；无加载或发布逻辑               |
| `src/engine/planet-loader.ts` | 下载、哈希、生成、还原、GPU 准备、缓存         |
| `src/engine/world.ts`         | 统一渲染器、光点、星球 LOD、相对坐标、地表查询 |
| `src/engine/warp.ts`          | 跃迁状态和就绪屏障；失败、取消与原位置保留     |
| `src/main.ts`                 | 启动、界面和调度装配                           |
| `scripts/sync-planets.ts`     | 独立仓库的不可变版本发布                       |
| `scripts/publish-pages.ts`    | 本地全量检查后发布可追溯的静态网站             |

## 代码规范

严格 TypeScript，禁止 any。协议输入必须先校验再使用；未知异常转换为可读错误。
不在渲染帧内下载或同步执行作者代码。任何跨边界输入均有大小与格式约束。
时间使用秒，位置为世界单位；首版按 1 单位约 1 米理解。玩家绝对位置不与渲染坐标混用。
异步加载使用显式状态；资源有明确所有者，卸载要释放材质、纹理、几何和 Worker。
新协议字段先写规范与失败测试，再加入运行时。不要为简单改色创建抽象框架。

## 验证

`npm run check`：静态检查、类型检查、纯逻辑/场景数据测试、生产构建。
`npm run test:e2e`：真实 Chromium，验证两星球、连续飞行、延迟加载跃迁、取消、禁网、超时和哈希失败。
`npm run publish:pages` 在发布前执行以上检查。生产构建使用 `/astra-universe/` 子路径。
当前网站由 `gh-pages` 静态分支发布；可选云端工作流等待账号账单问题解决后启用。

`window.__ASTRA__.snapshot()` 为只读观测：位置、状态、生成耗时、帧率与渲染资源数量。
它不提供移动、越权加载或更改世界的测试后门。

## 首版明确限制

仅桌面 Chrome/Edge，两个简单球体。没有推荐观景点、账户、社区和完整银河布局。
场景传递使用 Three.js 原生 JSON，较复杂作品可能在主线程还原时造成短帧。
两个星球保持驻留；大规模 LRU、分块地形及超大世界索引需要后续实现。
WebGL Shader 仍需人工复核性能，Worker 不能防止恶意 GPU 程序卡死。
静态代码文件缓存已实现；主站离线启动未配置 Service Worker。
